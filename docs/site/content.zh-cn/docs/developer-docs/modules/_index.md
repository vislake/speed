# 模块设计

[总体架构](/zh-cn/docs/developer-docs/architecture/)讲 speed 的形态,[设计原则](/zh-cn/docs/developer-docs/design-principles/)讲维持它的规则。本区落下第三层:**每个模块一页设计**——为什么长成这样、刻意不做什么、哪些契约已冻结。

## 本区与用户指南的关系

用户指南的[模块](/zh-cn/docs/user-guide/modules/)页回答*怎么用*:怎么安装、怎么接线、怎么调用。本区页回答*为什么*:每个模块的职责与边界(包括它拒绝做的事)、机制背后的设计思路、被权衡过的取舍,以及消费者可以依赖的稳定面。两种视角互补并互相链接;让你意外的设计论断,可以按该页 Source 小节指名的源文档核对。

## 读序

先读总体架构与设计原则,再读组的导览再读模块页——每份组导览以每模块一句话讲清组内分工与依赖链。模块页自身按依赖序排列,一组自上而下读就是一个完整的设计故事。

## 分区结构

模块空间与用户指南同样分组:

- **core(底座)**——每个二进制都要组装的依赖地板:装配契约、数据层、租户解析、可观测性、动态配置、任务队列与限流。
- **services(服务)**——平台业务形态的服务(对象存储、通知,及其上各模块)。
- **identity(身份)**——认证与授权:调用者是谁,从不决定他能做什么。
- **capabilities(能力)**——计量、计费、分享与建立在它们之上的外向表面。
- **app(装配层)**——在其余各组之上的装配层:唯一没有业务域的模
  块,装载器、八阶段组件驱动、固定中间件链与无 import 桥接都在
  此,宿主不再重写共享启动胶水。
- **tools(工具)**——面向开发者与运维者的工具。

## Source 约定

本区每页都是提炼,绝不是拷贝:原材料是各模块自己的 `AGENTS.md`——随模块交付给消费项目的模块级纪律文档。内部审议过程、未决跟踪项与发布排期不进这些页面;每页带 Source 小节链回本模块的 AGENTS.md,任何论断都可核对底层文档,并带"相关页"小节链接本区邻居与对应用户指南页。
