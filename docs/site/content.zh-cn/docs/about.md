# 关于 speed

speed 是以库分发的模块化单体:独立发布的 Go 模块与 npm 包,业务项目
通过 `go get` / `npm install` 拉入并编译进一个二进制。它不是一个你
直接运行的应用,也不是一个你 fork 的仓库——你通过一次装配把产品
需要的模块组合起来,并完全拥有产物。

| 决策 | 在实践中意味着什么 |
|---|---|
| 形态:模块化单体 | 模块编译进你的二进制、进程内互相调用——无服务发现,模块之间无网络跳。 |
| 分发:以库 | 每个导出的签名变更都会传播到每个交付项目,所以公开 API 冻结,除非刻意发布破坏性变更;每加一个依赖都会落进别人的 `go.sum` 或 bundle;实现细节住在 `internal/` 下。 |
| 部署模式与组装 | 两条正交轴。每条基础设施依赖都是带多个实现的接口(一个进程内实现,加 PostgreSQL、Redis、S3 等其他后端)。**部署模式**不选择实现,它只约束实现:每个实现声明能力,当组装不能满足声明的模式时启动失败。单进程部署可以连真实外部服务。业务代码绝不按模式分支。 |
| 多租户 | 共享数据库以 `tenant_id` 隔离,由 GORM 插件、强制的泛型仓库基类与分布式模式下的 PostgreSQL 行级安全三道守护。 |
| 版本化 | 锁步:所有模块与包共享一个版本并一起发布;只支持同版本组合。 |

## 文档如何分发

每个模块在模块内随附自己的 `AGENTS.md`——给任何与它打交道的人
(人类或 AI 工具)的向导:职责与边界、公开 API、接线要求、已知限
制——所以文档随代码走,并与消费者实际拉取的版本保持同步。

本站是跨模块的集中参考,分两个主栏目:[用户指南](/zh-cn/docs/user-guide/)
(用 speed 搭建你的 SaaS)与[开发者文档](/zh-cn/docs/developer-docs/)
(开发 speed 本身),各带逐模块读法。模块页链接该模块自己的
`AGENTS.md` 作为权威描述。

站根 [/llms.txt](/llms.txt) 携带全部内容的机器可读索引。
