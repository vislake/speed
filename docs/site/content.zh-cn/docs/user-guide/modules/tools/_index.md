# 工具组

本模块参考里的其它分组,文档化的是你组装进二进制的模块:`go get`
它、经 `pkgcore` 注册、在 `Kernel` 里启动它。本组文档化的是唯一
一个不是模块的条目:**saasctl**,speed 面向业务方的 CLI——塑造业务方
实际运行的那个应用的工具。业务方拥有自己的代码;saasctl 管理的是
项目与它拉入的 speed 模块之间的边界:

- `new` 从内嵌模板树生成一个可直接启动的起始项目到新目录;
- `upgrade` 把项目的 `github.com/vislake/speed/go/*` require 重写到
  同一个锁步发布版本;
- `db migrate` 把项目所要求的、带迁移文件的模块的 SQL 迁移应用到
  它的 SQLite 数据库;
- `config print` 展示生成项目启动配置的解析结果,密钥行一律
  `[redacted]`。

没有任何东西会把 saasctl 组装进运行中的服务。它不实现
`pkgcore.Module`,从不注册进 `Registry`,业务方代码从不 import 它;
参考应用也刻意不接它——它的消费方是那些生成项目本身。模块各页
回答「我要把模块 X 集成进我的二进制」,本页回答「我要开始或维护
一个基于 speed 的项目」:工具在开发期作用于项目边界——创建目录、
编辑 `go.mod`、给数据库文件应用 schema——在启动之前与启动之外,
从不进入启动本身。

## 何时用到它

- **从零开始**——`new` 是开新项目的标准入口;[快速开始](/zh-cn/docs/user-guide/quickstart/)
  把一次生成、迁移、启动完整走了一遍。
- **启动之前**——`db migrate` 在任何进程运行前把 schema 就位,
  `config print` 在你启动之前展示这次启动会用什么配置。
- **发布之时**——`upgrade` 把项目的整个兼容面迁到发布所带的那个
  版本上。
- **围绕项目**——[参考应用演练](/zh-cn/docs/user-guide/walkthrough-reference-app/)
  与[生成项目的运维](/zh-cn/docs/user-guide/operating/)两页覆盖
  运行中产品的组装形态与日常命令;本组的这一页是两者底下各自的
  完整参考。

## 本组页面

| 页面 | 给你什么 | 典型首次使用 |

| [saasctl](/zh-cn/docs/user-guide/modules/tools/saasctl/) | 全部四个命令——用法、选项、校验与退出码——外加 `new` 生成项目的形态与工具的边界规则 | 生成那个随后由快速开始迁移并启动的项目 |

本页遵循组内约定:工具做什么(包括它刻意**不**做什么)、何时使用、
完整命令面、生成项目的解剖,以及边界与注意。页末的 Source 一节链
接 `go/saasctl` 自己的 `AGENTS.md`——那仍是权威、始终最新的契约,
本站页面只是它的浓缩。

本参考按依赖方向排序这件事对这里不适用——saasctl 在模块图之外,
不在任何东西之上,也不在任何东西之下。它是开发者工具,不是平台
能力面:它没有自己的表、迁移、HTTP fragment 或权限,运行中的产品
也永远不会从它这里服务出任何 `/api/v1/*` 路由。
