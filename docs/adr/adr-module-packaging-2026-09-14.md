# 接口包暴露它所封装的第三方库

## 状态

已接受

## 背景

speed 的一部分模块就是某个第三方库的封装：数据库模块封装 GORM，遥测模块封装追踪的 API 包。这类模块的功能接口要表达的东西——查询构造器、跨度、属性——已经由被封装的那个库定义。

发布单元按功能划分，绑定具体后端与驱动的实现位于子包（[ADR-module-packaging-2026-09-13](adr-module-packaging-2026-09-13.md)）。该记录把接口包描述为不引入第三方依赖的一层，而封装型模块的接口无法在这个限制下表达。

宿主的依赖清单由它 import 的包精确决定。除 `pkg/core` 之外，每个模块都是可选的：不 import 数据库模块的宿主，依赖图中不出现 GORM。

## 考虑过的选项

### 接口包另造一层等价抽象

接口包定义 speed 自己的类型，与被封装库的类型一一对应，实现子包在两者之间转换。

**否决**：抽象与被封装库的能力面一一对应时，它不隔离任何东西，只是给同一组概念起了第二套名字。依赖方为了使用该功能要在两套类型之间来回转换，被封装库的生态——它的插件、它的扩展点、围绕它的既有代码——在转换之后一概用不上。抽象还要随被封装库的演进同步扩张，每一次扩张都是接口包的改动。

### 接口包只暴露被封装库中不随实现而变的那部分

按"换掉该功能的任一实现，这个类型是否仍然原样出现"划界，只有满足的类型可以出现在接口面上。

**否决**：判据对封装型模块不成立。数据库模块换掉 GORM 就不再是同一个模块，被封装的库不是它的某个实现选项，而是它的形态本身。按该判据，封装型模块的接口面为空。

### 接口包暴露它所封装的第三方库

接口包用被封装库的类型表达功能接口，实现子包绑定具体的后端与驱动。

**采纳**，见决策。

## 决策

采纳：接口包可以暴露它所封装的第三方库；实现子包绑定具体的后端与驱动。

划界依据是这个模块与那个库的关系，不是这个库是否属于第三方：模块封装该库时，用它的类型表达接口是正常形态；模块只是碰巧用到该库时，那是实现绑定，留在子包。

`pkg/core` 不适用本记录，它零第三方依赖，依据是它被每一个模块 import（架构不变量 1）。

## 后果

封装型模块的接口面直接可用：被封装库的插件机制、扩展点与围绕它的既有代码，依赖方原样使用，不经转换。

接口包暴露了哪些第三方类型，由它自己的设计文档交代。

**接受的代价：**

- 接口包封装的那个库传染给每一个依赖方。取用该功能即承受它，与实现子包绑定的驱动不同，后者可以换掉。
- 被封装库的破坏性变更直达接口面。它的一次不兼容升级就是该模块的一次不兼容升级，无法在实现子包内部消化。
- 判据依赖"封装"与"碰巧用到"的区分，而这个区分没有编译器强制，由评审裁定。

## 失效条件

若某个封装型模块的依赖方普遍只用到被封装库的一小部分，且该模块出现了第二种不基于原库的实现，则该模块的接口面需要重新锚定，本记录对它不再适用。
