# 一个入口模块承载多个具名监听端

## 状态

已接受

## 背景

业务流量与管理流量要分别暴露。健康检查、指标与诊断面向运维网络，业务 API 面向外部调用方，两者的可达范围不同，因而要落在不同的监听端上。

模块名在进程内唯一，同名登记是登记那一刻就暴露的冲突（见 [core](../design/modules/design-core.md)）。

模块之间不按名称取用（架构不变量 9）。该条约束的是取得另一个模块产物的途径。

每个监听端有自己的地址、超时与中间件链：认证与限流属于业务端，管理端不经过它们。

## 考虑过的选项

### 一个模块一个监听端，管理面另立模块

入口模块只管一个监听端，管理端由另一个模块自己监听。

**否决**：管理面模块要把监听、排空、链组装与登记面重复实现一遍。两套实现此后各自演化，而停机时序与链组装正是最不应该有两个版本的部分。

### 每个监听端一个模块实例

同一实现子包登记多次，每个实例持有一个监听端。

**否决**：模块名进程内唯一，同一实现登记两次即重名冲突，要为此引入工厂式登记；多个实例交付同一功能，还要面对排他消解，而它们本不冲突。

### 一个模块多个具名监听端

一份配置中声明多个具名监听端，登记时指定落在哪一个。

**采纳**，见决策。

## 决策

采纳：入口模块在一份配置中声明多个具名监听端，每个有自己的地址与超时；登记路由与中间件时指定端名。

端名是本模块配置内的标识，不是模块名。取用本模块的功能仍然只经功能标识，架构不变量 9 约束的是取得另一个模块产物的途径，端名不是那个途径。

登记到未声明的端名即启动失败，不回落到任何默认端。

## 后果

管理面与业务面共用同一套监听、排空与链组装，只有一份实现。

每个端有自己的中间件链，认证与限流可以只加在业务端。

端名错写在启动时暴露，而不是表现为一条访问不到的路由。

**接受的代价：**

- 登记面上多出一个端名参数，只用一个端的宿主同样要面对它。
- 端名是字符串，登记方与配置之间的对应靠启动期校验建立，编译器不参与。
- 全部监听端共享本模块的生命周期：任一端绑定失败即整体启动失败，已绑定的其余端随之释放。
