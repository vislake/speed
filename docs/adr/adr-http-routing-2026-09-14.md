# 路由在 Init 阶段经登记面绑定，Spec 只承载元数据

## 状态

已接受

## 背景

handler 是模块在 `New` 中构造出的产物的一部分。描述符在 `init` 期登记，那时任何实例都不存在，handler 因而放不进静态的资源声明。

资源是静态声明，`Run` 之前确定、此后不变；需要依赖配置才能决定的东西是运行期交互，由模块在 `Init` 阶段取到对方的功能后调用其方法登记（[ADR-module-resources-2026-09-13](adr-module-resources-2026-09-13.md)）。该记录把"提供哪些 HTTP API"列为资源的用途之一，资源类型 `http.Spec` 由入口模块定义。

一条路由是否挂载可以取决于配置：模块按自己那份配置决定启用哪些 API，而配置要到 `Prepare` 之后才可读。

最终的 handler 在 `Serve` 阶段组装一次，此后不再变化。

## 考虑过的选项

### Spec 是权威，登记必须与它一致

`Spec` 静态声明全部路由的形状，`Init` 阶段的登记只负责绑定 handler，两者按路由键比对，缺失或多出即启动失败。

**否决**：比对成立的前提是每条路由都能在 `init` 期写出，而按配置决定是否挂载的路由写不出来。强制一致会把"这条 API 本次不启用"变成启动失败，或者迫使 `Spec` 承载它表达不了的条件。

### 取消 Spec，路由只由运行期登记决定

不设静态声明，模块提供哪些 API 只能从登记面的运行期状态读出。

**否决**：提供哪些 API 是模块的静态事实，文档合并、网关配置与权限清单都在进程之外读取它。取消 `Spec` 会让这些用途只能从一个运行中的进程反推。

### Spec 只承载元数据

`Spec` 声明模块提供哪些 API 供装配之外的用途读取，不参与路由；路由完全由 `Init` 阶段的登记决定。

**采纳**，见决策。

## 决策

采纳：路由由模块在 `Init` 阶段经入口模块的登记面绑定 handler；`http.Spec` 是静态元数据，不参与路由。

登记面只在 `Init` 阶段接受写入，此外的写入一律失败。最终 handler 在 `Serve` 阶段组装一次，晚到的登记进不了任何链，而被静默忽略的登记比一次响亮的拒绝更坏。

## 后果

按配置决定是否挂载的路由可以正常登记，不挂载不构成失败。

`Spec` 供装配之外的用途读取，其内容不随一次具体装配变化。

写入闸门把接线错误暴露在发生的那一刻，而不是留到某条路由访问不到时。

**接受的代价：**

- `Spec` 与实际登记是两份各自维护的事实，会走叉。两者不符不产生任何失败信号，属于"声明与实现不一致且无人察觉"这一类失效。
- 一条路由是否真的存在，只能在运行期观察登记面或访问它。
- 静态元数据的价值取决于声明方维护它的自觉，而不维护的代价不落在声明方身上。
