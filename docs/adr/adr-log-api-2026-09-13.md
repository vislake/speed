# 日志以标准库 slog 为调用面

## 状态

已接受

## 背景

日志被每一个模块使用，调用面一旦确定，全部模块的日志调用点都绑定其上，更换的代价随模块数量增长。

`log/slog` 是标准库，提供结构化日志的记录、属性与后端扩展点 `slog.Handler`。接口包不引入第三方依赖这条架构不变量因此不构成障碍。

`slog.Handler` 已是后端接入点的通用形态，主流第三方日志库都提供了对它的适配。

功能标识的元素类型必须是接口，`*slog.Logger` 是具体类型，不能直接作为模块之间取用的功能。

## 考虑过的选项

### 定义自有的日志接口

根包定义 `Logger` 接口，方法为 `Debug`/`Info`/`Warn`/`Error` 与 `With`，每种后端各写一层适配。

**否决**：调用点绑定在一套与标准库能力重合的 API 上，而这套 API 要重新定义 slog 已经定义的语义——属性分组、级别判断、记录裁剪。`slog.Attr` 的免分配路径经过 `...any` 适配层后失效。后端适配的形态也要另起一套：`slog.Handler` 是后端接入点的通用形态，自有接口与它不相容，本项目自己实现的后端也无法再作为 `slog.Handler` 被复用。

### 每种后端各登记一个日志模块，功能接口是按名取 logger 的工厂

`log/text`、`log/json`、`log/file` 各自登记一个模块并实现同一个工厂接口，宿主 import 哪个就用哪个。

**否决**：按模块命名、按模块过滤级别、上下文存取与脱敏都与后端无关，这样划分会让它们在每个后端里各实现一遍并逐渐分化。这些逻辑可以在根包的处理链里实现一次并对全部后端一致生效，后端只需回答"记录怎么编码"与"字节往哪写"，这正是格式与目的地的划分。该划分还让格式与目的地自由组合，而按后端分模块的做法要为每种组合各准备一个模块。

### 以 slog 为调用面，格式与目的地做成扩展点

根包定义格式与目的地的接口，实现位于子包，以资源声明交付，装配时按名匹配。

**否决**：本模块的格式与目的地都只用标准库——文本与 JSON 是 slog 自带的 handler，标准输出与文件是 `os` 的能力。拆成子包因此没有依赖隔离的收益，而隔离第三方依赖是拆子包的理由（[ADR-module-packaging-2026-09-13](adr-module-packaging-2026-09-13.md)）。扩展点要付出接口、资源收集与按名匹配的机制，为一个闭集付出这些换不到任何东西。

### 以 slog 为调用面，格式与目的地内置于根包

模块调用点直接使用 `*slog.Logger`；根包交付按名取 logger 的功能，其实现唯一；格式与目的地是根包内置的闭集，由配置按名选定。

**采纳**，见决策。

## 决策

采纳：日志的调用面是标准库的 `*slog.Logger`，本项目不定义自己的日志 API。

模块之间取用的功能是 `log.Logger`，它按模块名交出 `*slog.Logger`，并交出脱敏规则的登记接口。该功能的实现唯一，位于 `pkg/log` 根包，处理链在此组装。格式与目的地是根包内置的闭集，由配置按名选定，不经由多个日志模块，也不经由扩展点。

## 后果

模块的日志调用点使用标准库类型，不依赖本项目的任何日志 API。宿主已有的 slog 用法——`slog.Attr`、`slog.Group`、`WithGroup`——直接可用。第三方 `slog.Handler` 不可用：格式与目的地是内置闭集，处理链不接受外部 handler。

宿主只 import `pkg/log` 一个包即可得到全部格式与目的地，装配时无需按组合挑选 import。根包保持零第三方依赖。

**接受的代价：**

- `*slog.Logger` 与 `slog.Handler` 进入模块作者与本模块之间的契约。标准库对它们的演进本项目无从控制，其行为变化会直接到达全部调用点。
- slog 丢弃 `Handler.Handle` 的返回值，写入失败在调用点不可见。失败的处置因此只能由目的地实现自己承担。
- 调用点能够绕过本模块直接构造 `*slog.Logger`。这样得到的 logger 不经过处理链，脱敏不生效。
- 新增一种格式或目的地是根包的代码变更，宿主无法自行添加。带第三方依赖的目的地出现时要先开扩展点，那次变更落在根包，配置面不受影响。

## 失效条件

`log/slog` 不再是 Go 生态记录结构化日志的通用调用面，则本记录的前提不再成立：以它为调用面的价值在于宿主、第三方库与本项目共用同一套日志类型，生态转向之后这一点不复存在，而把标准库类型钉进契约的代价照旧。

出现一种需要第三方依赖的目的地时，内置这一半不再适用：该实现必须位于子包，届时格式与目的地要改为扩展点。
