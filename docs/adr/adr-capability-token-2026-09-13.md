# 功能以类型化空指针指代

## 状态

已接受

## 背景

交付声明、依赖声明与取用这三处都需要一个值来指代"某种功能"。三处的含义完全一致：提供这种功能、需要这种功能、取用提供这种功能的实例。它指代的始终是功能，不是某个特定实例。

注册表不认识任何具体功能，无法为取用的返回值给出静态类型，方法这一层因此返回 `any`。

功能标识要直接写在描述符的字面量里，因此它的构造方式不应依赖一个专门的构造函数。

## 考虑过的选项

### 反射类型

`type Token = reflect.Type`，构造用标准库的 `reflect.TypeFor[Cache]()`。静态类型明确，传错东西编译不过，构造函数来自标准库，不必由 `core` 自己提供。

**否决**：每个模块的声明都要 import `reflect`，写法比字面量啰嗦一截，而它换来的静态检查仅覆盖"这是一个类型"，并不能阻止填入一个无关的类型。

### 约定的字符串常量

`type Token = string`，功能的定义方导出常量，使用方 import 该包取用。写法最简单，拼写错误由常量在编译期挡掉，且能出现在配置与诊断输出中。

**否决**：注册表无从知道一个名字对应哪个 Go 类型，也就无法在构造完成时校验交付物确实实现了该功能。声明了某个名字却交付别的东西，注册表照单全收，错误推迟到某个消费方断言失败时 panic，现场已经离声明很远。名义匹配同时丢掉了"取用后的断言必定成功"这一保证。

### 类型化空指针

`type Token = any`，写作指向功能接口的类型化空指针 `(*Cache)(nil)`。匹配规则是"可赋值给该接口类型"。

**采纳**，见决策。

## 决策

采纳：功能以指向其接口的类型化空指针指代，交付声明、依赖声明与取用三处使用同一形式。

注册表在 `Register` 中校验每个此类值确为类型化空指针，不合法的当场 panic。

## 后果

功能就是"能做什么"，接口正是类型系统中表达它的方式，指代形式与被指代的概念因此一致。

匹配规则是可赋值性：模块的产物必须可赋值给它所声明的功能接口，取用所得的值断言成该接口因而必定成功，返回 `any` 让调用方失去的是编译期类型，不是运行时的类型正确性。

这说的是产物与接口之间的关系。一个功能标识与另一个功能标识之间不按可赋值性匹配，而按元素类型相同，否则排他消解无法为「该功能的提供者」定出唯一的分组；该规则见设计文档。

注册表能在构造完成时校验交付物确实实现了所声明的功能，偏离在产生它的那次构造上暴露。

写成字面量即可，描述符中的声明不调用任何函数。

**接受的代价：**

- 静态类型退化为 `any`。写成 `Cache(nil)`、误传一个实例或填入无关类型，编译器都不拦，只能靠注册期校验在登记的那一刻暴露。
- 功能没有可供人书写的名字，无法出现在配置中；配置里既不出现功能也不出现模块名，模块的配置段由它自己声明的命名空间定位。诊断输出可以用反射取到的接口类型名指代功能，但那是 Go 类型名，不是产品概念名。
- 写法对不熟悉这一约定的人不直观，`(*Cache)(nil)` 需要文档解释才能读懂其意图。

## 失效条件

若出现需要在配置中直接指定功能的场景，类型化空指针无法表达，届时需要为功能补一个可书写的名字，并承担名字与类型之间的映射。
