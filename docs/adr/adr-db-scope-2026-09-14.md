# 数据库模块承担自足的横切能力，需要上层概念的经插件扩展点接入

## 状态

已接受

## 背景

数据库之上有一批横切能力：软删除、字段级加密、按租户过滤、审计捕获。它们的共同点是必须作用于每一条语句——遗漏一条，它要防的事情就发生了，且不会在该条语句上显形。

这些能力需要语句级的拦截点：知道这条语句作用于哪个模型、要读还是要写、条件里已经有什么。GORM 的回调链与字段序列化机制提供了这个拦截点，而数据库模块封装 GORM，它交付的句柄就是 `*gorm.DB`（[ADR-module-packaging-2026-09-14](adr-module-packaging-2026-09-14.md)）。

它们对语句之外的东西的需求并不相同。软删除要的是一个删除时间列，字段级加密要的是一份密钥，两者都不必知道是谁在发这条语句、为了什么；按租户过滤要知道当前是哪个租户，审计捕获要知道操作者是谁、记录写到哪里去。

租户标识与操作者身份产生于依赖图上层的模块。数据库模块被每一个访问库的模块依赖，位于它们之下。

密钥不能存放在它所保护的那个库里——那样要先有密钥才读得出密钥。它因而只能在数据库之外给出，按配置与设置的划界判据落在配置一侧（[ADR-config-scope-2026-09-13](adr-config-scope-2026-09-13.md)）。

## 考虑过的选项

### 数据库模块承担全部四种能力

模块内建按租户过滤与审计捕获，模型实现约定的标记接口即自动生效。

**否决**：租户标识与操作者身份产生于依赖图上层的模块，数据库模块反向依赖它们会成环；把它们下沉到数据库模块自己定义，则每一个需要租户标识而不访问数据库的模块——注入点、认证、日志——都要为取得一个标识而 import 数据库模块。该选项还替每一个宿主决定了它是多租户的，单租户应用同样要带着这套概念和它施加的模型约定。

### 四种能力一律由上层模块经扩展点接入

数据库模块只交付连接与迁移，每种横切能力各由一个模块承担，声明自己的插件。

**否决**：软删除与字段级加密不需要任何上层概念，把它们推到模块外面，每个项目要各自重做一遍——而它们恰恰属于"漏一条就失效"的那类能力，分散实现正是漏的来源。软删除更是 GORM 自己就提供的，在外面重做一遍还要绕过它已有的机制。

### 按是否需要上层概念划分

不需要的由数据库模块承担，需要的经插件扩展点接入。

**采纳**，见决策。

## 决策

采纳：数据库模块承担不需要认识上层概念的横切能力；需要上层概念的经插件扩展点接入。

**判据是：除了这条语句本身，该能力还需不需要一个产生于依赖图上层的概念。**

不需要的由数据库模块承担。软删除只需要一个删除时间列，字段级加密只需要一份来自配置的密钥，两者都在数据库模块自己够得着的范围内。

需要的经扩展点接入：模块以资源声明交付自己的 GORM 插件，数据库模块在建立连接后、交付实例之前按依赖序逐个安装。按租户过滤要知道当前租户，审计捕获要知道操作者与记录的去向，两者都产生于数据库模块之上。

数据库模块不解释插件的内容，也不认识任何一种插件所实现的能力。

## 后果

软删除与字段级加密是取用数据库功能就得到的东西，模型按约定声明即生效，不需要额外装配一个模块。

租户隔离由租户模块实现，它定义自己的模型约定与标记接口，声明自己的插件；数据库模块不认识租户。审计捕获同理。

不装配这些上层模块的宿主不承受它们的约定：模型不必带租户标识列，也不必实现它们的标记接口。

插件在实例交付之前全部装好，取用方不存在拿到未装插件实例的路径。

**接受的代价：**

- 判据依赖"产生于上层的概念"这一区分，而新出现的能力未必一眼看得出落在哪边。一种能力先按自足实现、后来才发现它需要操作者身份，改归属就是一次跨模块的搬迁。
- 插件之间的相互顺序要由声明它们的模块用依赖声明表达。注册到 GORM 同一个处理器的多个插件，回调链次序取决于安装次序，而这一点在各自的插件代码里看不出来。
- 数据库模块无法校验插件装对了。它不认识插件的内容，一个声明了却对某类模型不生效的插件，在这里表现为安装成功。
- 按租户过滤在框架层没有机制保证。承担它的模块不被装配时，遗漏过滤不会被任何一层拦下。

## 失效条件

若出现一种横切能力，其拦截需求 GORM 的回调链与字段序列化机制都表达不了，则该能力既不能由数据库模块承担，也无法经本记录的扩展点接入，数据库模块的交付面需要重新裁定。
