# 入口模块的登记面锚定标准库 net/http

## 状态

已接受

## 背景

入口模块交付路由与中间件的登记面。登记面上的类型跨发布单元流动：业务模块在这里绑定自己的 handler，横切模块在这里贡献自己的中间件，这些类型因而出现在每一个带 API 的模块的接口上。

接口包可以暴露它所封装的第三方库，划界依据是模块与该库的关系——模块封装该库时用它的类型表达接口是正常形态，模块只是碰巧用到该库时那是实现绑定（[ADR-module-packaging-2026-09-14](adr-module-packaging-2026-09-14.md)）。

本模块的功能面是一组装配概念：多个具名监听端、路由与中间件的登记、中间件的跨模块排序、与生命周期各阶段的接驳。这些概念都不出自任何 HTTP 框架。

关联字段经 `context.Context` 传递，请求路径上的日志调用从上下文取 logger（[ADR-log-context-2026-09-13](adr-log-context-2026-09-13.md)）。

架构把 HTTP 与 gRPC 并列为入口形态，二者都是模块，都在入口阶段开始监听（[ADR-core-scope-2026-09-13](adr-core-scope-2026-09-13.md)）。

## 考虑过的选项

### 锚定自带上下文类型的框架

登记面用 gin、echo 这类框架的 handler 与上下文类型表达，请求体绑定、参数校验与渲染随之进入登记面。

**否决**：这类框架的中间件是框架内部维护 handler 序列与游标的模型，由链自身驱动下一层。跨模块的排序合成要在其上另建一层，而"需要在被封装库之上另建一层"正是判定模块与该库不是封装关系的依据（[ADR-module-packaging-2026-09-14](adr-module-packaging-2026-09-14.md)）。

登记面的类型流向每一个带 API 的模块，锚定该框架等于让这些模块全部依赖它，取用其中任何一个的宿主都要承受同一个依赖。

换掉该框架，本模块的装配概念原样成立。被封装的库应当是模块的形态本身，而不是可以换掉的实现选项。

### 锚定 fasthttp 系的框架

登记面用 fiber 这类不基于 `net/http` 的框架表达。

**否决**：这类框架不以标准的 `context.Context` 承载请求范围的值，而关联字段的传递正建立在它之上（[ADR-log-context-2026-09-13](adr-log-context-2026-09-13.md)）。追踪标识与租户标识在这样的入口下到不了下游的日志调用。

### 把接口定义推向 protobuf 优先

登记面以 connect-go 这类方案表达，模块的 API 由 protobuf 定义，同一监听端同时服务 gRPC 与 HTTP。

**否决**：这是模块如何定义自己 API 的范式决定，作用范围远大于入口模块，应当单独裁定。它也不构成本记录的替代项——connect-go 本身以 `http.Handler` 收口，采纳本记录不妨碍将来以它作为实现子包。

### 锚定标准库 net/http

登记面用 `net/http` 的 `Handler`、`ResponseWriter` 与 `Request` 表达，中间件写作 `func(http.Handler) http.Handler`。

**采纳**，见决策。

## 决策

采纳：登记面用 `net/http` 的类型表达，中间件写作 `func(http.Handler) http.Handler`；绑定具体路由引擎的实现位于子包。

本模块与任何 HTTP 框架的关系是碰巧用到，不是封装：它的功能面是监听端管理、登记与排序、生命周期接驳，换掉路由引擎这些概念原样成立。

## 后果

业务模块只依赖标准库即可写出 handler 与中间件。

以 `func(http.Handler) http.Handler` 为形状的既有中间件可直接登记，不经转换。

实现子包可用标准库的 `ServeMux`、chi 或任何以 `http.Handler` 收口的引擎。gin 与 echo 的引擎同样以 `http.Handler` 收口，因而也可以作为实现子包。

Go 1 的兼容性保证覆盖登记面的全部类型。

**接受的代价：**

- 框架上下文自带的那一整套请求处理便利不随登记面而来。接口包以零依赖的工具补上 JSON 解码、校验的调用机制与 JSON 响应写出，覆盖面窄于框架自带的：tag 驱动的校验规则、多格式渲染与内容协商都不在其中，需要它们的 handler 自行解决。
- 以框架私有上下文为中心写成的既有 handler 不能原样登记，要在外面包一层适配。
- 某个框架成为事实标准时，登记面不会因此自动跟进；改换锚点是本模块接口面的一次不兼容变更。

## 失效条件

若业务模块普遍绕过登记面、各自持有自己的路由引擎并只把一棵子树挂进来，则登记面没有起到装配作用，本记录的锚点需要重新裁定。
